# Govee: a full music spectrum on every strip

Windows **1.26.3-dev.2** and Android **0.26.3-dev.2** (versionCode **115**), isolated development channel.

Every selected strip displays Resonance's complete six-color music palette from start to end. The same logarithmic 40 Hz–16 kHz spectrum spans each strip: bass at the start, mids in the middle and treble at the end. Local frequency energy controls each zone's brightness, with overall loudness adding intensity. Colors blend between zones on the host without wrapping treble back into bass. Attack, release and palette smoothing preserve continuity on pause and track changes. Music only continues to drive the real analyser without starting graphics.

Open **Settings → Room lighting → Find lights**, select the strips and **Start sync**. Old whole-strip selections migrate to the full spectrum. **Reverse strip** changes its physical direction. **Check strip ends** temporarily displays cyan → pink for 12 seconds, then returns to music. **Zones** is adjustable: the initial H61D3/H61D5/H61D6 estimates are 42/70/140, based on the owner's approximately 70-point 5 m editor, not a claimed LAN capability query. Discovery does not report native zone counts. If a gradient does not reach both ends, adjust this value; rediscovery preserves the correction.

Segmented output uses the reverse-engineered realtime `razer` LAN channel; Govee's documented LAN API only exposes whole-device color and brightness. Firmware compatibility and native resolution vary. Protocol references: [LedFx's Govee implementation](https://github.com/LedFx/LedFx/blob/main/ledfx/devices/govee.py), [Govee Toolkit protocol research](https://github.com/damient/govee-toolkit/blob/main/docs/protocol/lan.md). No cloud key, account credentials or music upload is required.

Commands are spaced per device, with bounded frames, brightness ceilings, deduplication and keepalives. A fresh power-on status is required before starting; reported power-off is respected. Firmware that suppresses status while streaming no longer causes a false twenty-second cutoff. Stop, deselection and publisher timeout release realtime control; Stop restores the brightness recorded before syncing. No power commands are sent. The original Govee scene cannot be read back or guaranteed restored. Sync remains per-session opt-in and stops when the app is hidden.

Verification includes a dim physical cyan-to-pink map on all four owner's strips; the owner confirmed that the gradient worked on all four. Automated tests cover packet golden bytes, large-frame lengths/checksums, no wrap, mapping/reversal, smoothing, caps, command ordering, status suppression, Stop snapshots, settings migration, private-address validation and publisher timeout. The actual Windows UI/analyser plays generated 80 Hz and 8 kHz tones and verifies that opposite ends brighten, followed by a smooth pause fade. The actual phone UI passes a native-bridge simulation with discovery, touch scrolling and Stop. Physical Android output is not claimed. Both ABI builds, device-test compilation, JVM tests/lint, signing, packaged startup graphs, empty-library Windows startup, frozen updater compatibility and anonymous development-channel isolation are verified before publication.

Development installations can update through **Settings → App updates**. Android retains the package and signing certificate and installs over the existing app; do not uninstall. The approved Windows 1.26.2 / Android 0.26.2-preview releases, `main` and live download buttons remain unchanged.
