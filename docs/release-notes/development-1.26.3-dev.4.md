# Faster Govee response and stronger frequency contrast

Windows **1.26.3-dev.4** and Android **0.26.3-dev.4** (versionCode **117**), isolated development channel.

Lighting output now targets **60 updates per second**, replacing the previous approximately 10 Hz ceiling. Ordinary pixel frames no longer inherit the 100 ms settling delay intended for mode changes. Brightness, arming and status commands retain their settling gaps. The publisher keeps only the current frame, with no growing queue. Android polls native analysis faster while lighting is active; normal mobile analysis defaults remain unchanged when it is off.

LEDs use a dedicated, unheld spectrum input instead of following the visual spectrum's smoothing and then adding another long tail. This input still passes through the existing audio-output synchronization buffer, including Bluetooth compensation. Frequency attack is 6 ms and the active-note release is 40 ms; pause retains a gentle 550 ms release. Palette changes remain smooth. The lighting sampler does not advance a visible scene or camera independently, and interleaved samples use actual elapsed analysis time.

Weak frequency leakage is gated and the brightness curve expands the difference between quiet and active zones. During playback the ambient gradient is darker, while loudness still controls the intensity of active zones without automatically clipping every peak. The existing quiet setting is now labelled **Paused glow**: its configured brightness returns gradually when playback pauses. All strips retain the same full palette and normalized frequency map, direction control and adjustable zone counts.

**Hardware limitation still under investigation:** the owner confirmed smooth motion on one 5 m controller with Wi-Fi firmware 1.01.17. A second H61D5 controller with firmware 1.06.24 still visibly stuttered when receiving the same approximately 62 FPS, 70-zone test pattern. Reducing the test rate and power-cycling that controller did not resolve the observation. All four devices acknowledge realtime mode. Network timing was also more variable on the stuttering controller. The owner reports that built-in Govee Home effects remain smooth on the affected strips. These observations do not prove a firmware defect or establish the devices' physical render rates. This build improves Resonance's output and contrast; it does **not** claim to fix the remaining stutter on every controller. An alternative indexed-pixel probe did not render on the tested device and is not included in the app.

Verification: **590 shared tests** and **157 Android JVM tests** pass. Coverage includes 60 Hz packet pacing, settling gaps around control commands, rapid attacks and short-note release, strong weak/active contrast, retained loudness variation, graceful pause, and synchronized delivery of the dedicated lighting input. The actual desktop UI/analyser passes generated 80 Hz and 8 kHz mapping tests with over 100 pixel frames during its initial 2.5-second sample. Phone UI simulation, both ABI builds and device-test compilation pass; Android lint reports **0 errors / 9 existing warnings**. Packaged startup graphs, empty-library Windows startup, signing identity and update-channel isolation are verified before publication. Physical Android output is untested.

Install through **Settings → App updates** on the development channel, then **Settings → Room lighting → Start sync**. Android keeps its existing package and signing identity and updates the installed app; do not uninstall. Main, ordinary releases and public download buttons remain unchanged.
